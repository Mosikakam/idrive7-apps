# BMW Weather Widget — состояние проекта

Дата фиксации: 10 ноября 2026 года.

## Краткий статус

Подготовлен исходный код пользовательского погодного приложения для MGU / iDrive 7. В проекте есть экран прогноза, анимированный домашний виджет `startWidget`, клиент Open-Meteo, манифест приложения и инструкция на русском. Приложение ещё не собрано в устанавливаемый пакет и не устанавливалось на автомобиль.

## Реализовано

- Получение текущих погодных условий и прогноза на пять дней через HTTPS-запрос к Open-Meteo.
- Отображение температуры, ощущения, влажности, ветра, погодного описания, дневного максимума/минимума и вероятности осадков.
- Рисование анимированных солнца, облаков, дождя и снега средствами canvas из MGU app kit.
- Экран приложения с кнопкой обновления и домашний виджет, который обновляется с умеренной частотой анимации.
- Период обновления по умолчанию — 30 минут; доступны 15 и 60 минут.
- Переключение °C/°F.
- Задана приблизительная точка центра Петропавловска-Камчатского (`53.017, 158.650`). Это координаты города, не машины или дома. Приложение отправляет их погодному API при запросах.
- Добавлена атрибуция Open-Meteo в интерфейсе.

Приложение не вызывает BMW Online/ConnectedDrive API и не пытается перенаправлять штатный трафик BMW.

## Совместимость HTTPS с Node.js 8 — 12 ноября 2026 года

Пользователь прислал фото экрана Weather 1.0.1 с ошибкой `"listener" argument must be a function`. Это происходит до сетевого подключения: приложение вызывало `https.get(url, options, callback)`, а поддержка отдельного аргумента `options` вместе с URL добавлена только в Node.js 10.9.0. MGU запускает приложения на Node.js 8. В версии 1.0.2 запрос переведён на совместимый вызов `https.get(options, callback)` с `hostname` и `path`. Тест теперь проверяет число и тип аргументов HTTPS-вызова, а также адрес Open-Meteo. Локальные синтаксические и функциональные тесты прошли. После обновления через MGU Store ещё требуется подтвердить ответ Open-Meteo и появление прогноза на плитке; возможные ошибки DNS/TLS/Internet Uplink пока не исключены.

## DNS через Internet Uplink — 12 ноября 2026 года

После обновления до 1.0.2 пользователь прислал фото с `Weather unavailable` и кодом `EAI_AGAIN`. Значит, вызов HTTPS теперь выполняется, но штатный resolver MGU не может разрешить `api.open-meteo.com`. В документации `mgu-uplink` указано, что системный resolver не обслуживает интернет-имена сторонних приложений: им выдаётся собственный `data/uplink.json` с DNS-серверами. Версия 1.0.3 добавляет `apps/bmw_weather/uplink.js`, который для HTTPS-запроса Open-Meteo читает только собственный файл подключения, передаёт его DNS-серверы в `dns.Resolver` и возвращает IPv4-адрес через опцию `lookup`; глобальные DNS и маршруты MGU не меняются. Если файла подключения нет, экран показывает `No Internet Uplink lease for Weather`; если в нём нет DNS, показывает отдельную ошибку. Тест с имитацией файла подключения и DNS проверяет выбор сервера и ответ, а также отсутствие файла. Синтаксис и JSON проверены. На автомобиле остаётся проверить наличие Internet Uplink и фактический HTTPS-ответ после обновления через Store.

## Нет файла подключения Weather — 12 ноября 2026 года

После обновления до 1.0.3 пользователь прислал фото `No Internet Uplink lease for Weather api.open-meteo.com:443`. Значит, Weather читает свой каталог данных, но `uplink.json` там отсутствует или не содержит IP. Это бывает, когда Internet Uplink не в состоянии Online либо когда Weather не зарегистрирован для маршрутизации. В опубликованном `app.json` флаг `mguInternet: true`, а `kit/tools/build.py` переносит его в `package.json`; по коду комплект должен запросить интернет-доступ. Документация mgu-uplink: lease создаётся только пока Uplink Online и приложение разрешено; deploy tool пишет `apps.d/bmw_weather` для приложений с флагом. Пользователю отправлен запрос о статусе Uplink в MGU Store. Если Offline, подключить Uplink; если Online, переустановить Weather через Store для повторной регистрации. Код приложения не менялся, штатные сервисы BMW не затрагивались. Пока статус и результат переустановки неизвестны.

## Uplink Online, Weather без lease — 12 ноября 2026 года

На новом фото MGU Store показывает зелёный статус `В сети`; Weather отображается как установленный. Следовательно, общий Uplink Online, но предыдущее сообщение Weather `No Internet Uplink lease` указывает на отсутствие его собственного файла подключения. Код и каталог на GitHub проверены: `mguInternet: true` задан в `apps/bmw_weather/app.json`, сборщик переносит флаг в `source/package.json`; путь `ctx.dataDir` соответствует каталогу `oap_<uid>/data` в runtime. По исходникам mgu-deploy приложение с этим флагом должно получить `/var/opt/mgu-uplink/apps.d/bmw_weather`, а mgu-uplink — создать `data/uplink.json` пока Online. Причина несоответствия на конкретном устройстве пока неизвестна. Пользователь подтвердил, что после появления ошибки ещё не переустанавливал Weather. Следующий шаг — переустановка Weather через Store для повторной регистрации; если lease не появится, нужны установленные `source/package.json`, `apps.d/bmw_weather`, registry UID и журнал mgu-uplink с MGU. Штатные BMW-сервисы не менять.

Сетевой доступ к Open-Meteo через конкретный автомобиль не проверен; после обновления нужен текст новой ошибки или успешный прогноз.

## TCP к Open-Meteo не устанавливается — 12 ноября 2026 года

Пользователь обновил Weather до 1.0.4 и прислал фото `Weather total timeout during TCP connection`. DNS и lease уже работают; TCP к `api.open-meteo.com:443` не установился за 40 секунд. Waze на автомобиле получает данные с телефона, поэтому его работа не подтверждает прямой интернет-доступ процесса Weather. Версия 1.0.5 сокращает ожидание заведомо неустановленного TCP до 15 секунд и только при такой ошибке пробует соединиться с `api.github.com:443` через тот же Internet Uplink без передачи HTTP-данных. Результат показывается на экране: если GitHub TCP доступен, проблема, вероятно, специфична для адреса Open-Meteo; если нет, требуется проверка маршрута/доступа приложения или настроенного прокси. Локальный тест имитирует таймаут Open-Meteo и успешное TCP-соединение с GitHub; синтаксис и JSON проверены. Реальную сеть автомобиля тест не воспроизводит.

## Резервный источник прогноза — 12 ноября 2026 года

На фото Weather 1.0.5 показано `Open-Meteo TCP timeout; GitHub TCP OK`: прямой TCP через Uplink доступен другому адресу, а соединение с `api.open-meteo.com` на этой сети автомобиля не устанавливается. Это не доказывает недоступность Open-Meteo во всей России. В версии 1.0.6 добавлен документированный JSON API `wttr.in` как резервный источник без API-ключа. При сбое Open-Meteo приложение запрашивает `wttr.in/<lat>,<lon>?format=j1`, преобразует температуру, влажность, ветер, погодные коды и доступный дневной прогноз в существующую модель, подписывает фактический источник и на шесть часов предпочитает работающий резервный адрес, чтобы не ждать повторяющихся TCP-таймаутов. Резервный API обычно возвращает три дня вместо пяти. Если оба адреса недоступны, приложение показывает обе причины и выполняет прежнюю проверку TCP до GitHub. Синтаксис, JSON и локальный тест с макетом обоих API, переходом на резервный и отрисовкой прошли. Доступность wttr.in именно через MGU ещё требует проверки на автомобиле.

## Облегчённый резервный запрос — 12 ноября 2026 года

На фото Weather 1.0.6 показано `Open-Meteo TCP timeout; wttr.in Weather idle timeout during response body`. Значит, wttr.in дал HTTP-заголовки, но тело ответа `format=j1` не завершилось до таймаута; причина на сервере или маршруте пока неясна. В версии 1.0.7 резервный запрос переведён на `wttr.is` — документированный проектом альтернативный домен — и уменьшенный JSON `format=j2` без почасовых данных. В интерфейсе дневные погодные значки не показываются при отсутствии кода, зато остаются текущие условия и дневные максимум/минимум. Таймаут бездействия резервного запроса сокращён до 12 секунд, а ошибка указывает число полученных байт. Локальный тест покрывает ответ j2, таймаут до первого байта и успешный переход на резервный источник. Результат на MGU ещё не проверен.
